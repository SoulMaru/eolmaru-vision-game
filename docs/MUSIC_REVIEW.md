# 빠른 테크노·댄스 음악 확장 독립 검토

검토엔진,2026-09-27 KST. 작업 전 기준 커밋은 `8e7971c`이며 git status가 비어 있음을 직접 확인했다. 검토엔진의 변경 범위는 `tests/review-music.test.mjs`와 이 문서,후속 요청으로 허용된 `tests/browser-saber-races.js`의 새 곡 경합 시나리오다. 앱·작곡기·음원·F 제작소는 수정하지 않았다.

## 기존 자산 기준과 보존

작업 전에 기존 Maru Flow/Breeze/Sunset의 Ogg3개·메타데이터 JSON3개·음성 manifest SHA-256을 직접 계산했다. 기대값은 검토 검사에 상수로 기록했으며 변경된 메타데이터로 기대값을 다시 만들지 않는다. 기존31개 음성 파일의 메타데이터/해시는 기존 profile 회귀가 검사한다. 전신 세트는 기존112BPM 세 곡의 앞75초씩 총225초를 유지해야 한다.

## 첫 직접 실행

기준 보존2개 검사 직접 통과(83.2ms). `src/songs.mjs`와 두 새 채보가 준비된 뒤 실제 독립 파일을6개로 확장하여 **6/6 통과,실패0,건너뜀0,103.8ms**를 확인했다. 원본 보존,카탈로그,96마디 길이 계산,배포 채보와 네트워크 응답 전 fallback 동일성,음악 시계·전역2박·마지막 유예,다른 곡 채보 거절이 범위다. 새 음원 파일이 완성되기 전 결과이며 오디오 디코드 완료를 뜻하지 않는다.

## 최종 음원과 직접 검사

최종 렌더 확정 뒤 새 파일/메타데이터 검사를 추가해 **음악9/9 통과,실패0,건너뜀0,126.4ms**를 확인했다. 이어 기존 회귀와 함께 `node --test tests/review-*.test.mjs`를 직접 실행한 결과는 **전체82/82 통과,실패0,건너뜀0,245.8ms**였다. 음원 검사는 단순 확장자 확인 대신 모든 Ogg 페이지/끝표본(EOS granule)·첫 Vorbis packet의 채널/샘플레이트·메타 크기/해시·작곡기 파일 해시를 대조한다. 이 Node 검사는 FFmpeg/Python/F드라이브 없이 실행된다.

별도 읽기 검증으로 두 배포 Ogg 전체를 `ffmpeg -v error -xerror -i <file> -f null -`로 디코드했다. 두 명령 모두 exit0,오류 출력0이었다. `ffprobe`와 `astats=metadata=0:reset=0`도 직접 실행해 아래 값을 확인했다.

Pulse의 설계 길이는147.692307692초,디코드 표본으로 계산한 길이는147.692312925초다. Ogg 끝표본/ffprobe 표시와 디코딩의 차이는1sample 이내이며,최종 비트스트림 검사도 이 조건을 통과했다. 이 작은 차이를 BPM 변경이나 채보 오프셋으로 보정하지 않는다. 제작기가 기록한 loudnorm 결과는 각각−14.01/−13.89LUFS,−1.50/−1.38dBTP다. 검토엔진이 독립 측정한 항목은 위 peak/RMS/표본/형식/해시이며 LUFS 수치를 다시 측정했다고 쓰지 않는다.

기존 음악3개와 메타3개·음성 manifest는 작업 전 고정 해시와 일치했다. 기존 profile 회귀에서31개 음성의 실제 바이트·해시도 통과했다. F 원본 `webtoon.py`를 읽기 전용 해시로 직접 확인한 결과는 `de182299dbf5216aaeaaa08303ae19c8785a537518b9ba1d3e44f6164edf3df3`로 기존/신규 제작 기록과 같았다. F 함수의 실제 호출은 생성엔진의 제작 수행이며 검토엔진은 호출 코드·기록·현재 원본 해시를 대조했다.

## 독립 브라우저 경합 회귀

새 `music-chart-races` 세션에 기존 지연응답 init script를 등록하고 매번 새 페이지에서 실행했다. 기존 `import`5/`editor`6/`file`8/`stale-editor`5의24개가 모두 다시 통과했다. 이어 `?race=fast-song`7개를 추가해 **총31/31 통과,CLI page errors0**을 확인했다. 마지막에 세션을 닫았다.

새 사례는 Flow 기본채보 fetch를 보류한 상태에서 Neon Drive를 선택하여 음원 경로·150BPM·153.6초·Neon 소유 채보를 확인한 뒤,늦은 Flow 응답을 해제한다. 이후 선택곡·재생 경로·BPM과 편집기에서 읽은 채보 전체가 이전 Neon 상태와 같았다. 기존 사례는 사용자 import/열린초안 보존,File.text 중 곡/BPM/Play/모드 잠금,새 revision 뒤 오래된 응답 거절을 확인한다. 카메라·비공개 state·앱 소스는 건드리지 않았다.

생성엔진은 별도 `browser-music.js`에서29/29 통과(새2곡 실제 재생,메타/HUD/채보,종료,취소/실패복원,정상 로컬파일,전신전환)를 보고했다. 이 보고는 검토엔진의 독립31개와 별도 수행 결과다. 이후 생성엔진이 추가한 검사가 있으면 최종 TEST_RESULTS에 최신 수행 결과를 기록한다.

## 검토 결론과 남은 범위

이번 확장에서 독립 검토가 발견한 미해결 차단 결함은 없다. 기존 음악·전신·음성 보존과 새2곡의 파일/음악시계/선택 경합을 개발 검사 범위에서 수락한다. 사람 청취·취향·실제 스피커 음량 균형·카메라 플레이의 편안함/체감 박자는 여전히 미검증이며 자동 결과로 완료 처리하지 않는다.
