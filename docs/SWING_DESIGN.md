# 0.8 팔과 손 이동에 반응하는 검

작성일: 2026-09-27 KST. 생성엔진 작업 기준: clean `241c02a`. 소유 변경: `src/saber-input.mjs`, `src/saber-render.mjs`, 신규 `src/saber-swing.mjs`, 이 문서. 게임 흐름·튜토리얼·판정·효과음 모듈과 기존 음악·이미지·목소리는 수정하지 않았다.

## 결과와 판정 계약

카메라의 팔꿈치→손목 방향이 검의 기본 방향을 정하고, 실제 손 이동 방향과 속도가 약간의 추가 기울기를 만든다. 마우스/키보드 시험 입력은 손 이동 방향으로 검을 회전한다. 검 몸체·손잡이·장갑과 각 프레임의 잔상이 함께 회전한다. 밝은 검 끝은 기존 관측 손목 좌표 그대로이며, 회전된 검 몸체를 충돌 판정에 사용하지 않는다.

기존 `SaberGame.sample()`의 `{...point}` 전달과 `HandTracker.display()` 연결을 그대로 이용했다. `core`나 채보/등급/효과음 코드는 각도 필드를 읽지 않는다. 실제 손 좌표 `x/y`, sample 타임스탬프, segment의 `from/to/distance/speed/vector`, 스트로크 및 판정 로직은 기존 수식을 유지한다.

## 입력/표시 API

| 위치 | 필드 | 의미 |
| --- | --- | --- |
| `poseHand()` 결과 | `armAngle?: number` | 신뢰할 수 있는 팔꿈치→손목의 Canvas 회전 라디안 |
| `HandTracker.display()` | `bladeAngle: number` | 현재 표시할 장식 각도; 유효 손에만 있음 |
| `HandTracker.display().trail[]` | `bladeAngle: number` | 해당 관측 시각의 검 각도 |
| 같은 trail 항목 | `swing: boolean` | 실제 이동 속도가 기존 이동 문턱 이상인지 여부; 시각 잔상만 사용 |

`saber-swing.mjs`는 DOM/브라우저 전역 없이 import할 수 있는 순수 함수 모듈이다. 공개 함수는 `defaultBladeAngle`, `initialBladeAngle`, `nextBladeAngle`, `angleDelta`, `bladeGeometry`다. `SWING_MAX_RADIANS_PER_SECOND=10`, `SWING_ANGLE_DEADBAND=.025`를 공개해 검사 기준을 고정한다. 각도 단위는 라디안이며 0은 검 끝이 손잡이 바로 위, π/2는 검 끝이 손잡이 오른쪽인 화면 회전이다.

팔꿈치는 왼손13/오른손14, 손목은15/16을 사용한다. 좌표는 이미 앱에서 화면용으로 반전된 pose를 따른다. `dx=(wrist.x-elbow.x)*calibration.aspect`, `dy=wrist.y-elbow.y`, `armAngle=atan2(dy,dx)+π/2`다. 카메라 가로/세로 비율을 보정한 뒤 각도를 계산하므로 가로 화면 때문에 방향이 눌리지 않는다. 팔꿈치/손목의 visibility가 .55~1이고 유한 좌표여야 한다. 화면에 투영된 팔 길이가 .035~.8 사이일 때만 팔 방향을 채택한다. 매우 짧게 보이거나 비정상적으로 긴 팔은 각도 필드를 생략하고 유효 손목의 판정 좌표는 유지한다.

## 관측 기반 회전과 잔상

검은 실제 입력 관측에서만 각도를 갱신한다. 믿을 수 있는 팔 방향이 있으면 그것을 기준으로 하고, 손의 이동 방향에 속도 가중치를 더하되 최대 약23도 추가 기울기로 제한한다. 팔 각도가 없을 때는 실제 이동 방향을 사용한다. 신뢰할 수 있는 팔이나 이동이 아직 없으면 기존 좌우 기본 기울기를 사용한다.

최단 회전각으로 -π/π 경계를 넘으므로 불필요한 한 바퀴 회전은 없다. `1-exp(-dt/.055)`의 시간 기반 응답과 초당10rad 상한을 함께 적용한다. 관측 간격이 .2초를 초과하면 이전 장식 각도를 연결하지 않는다. .025rad 미만의 팔 변화는 보류하며 마지막 채택한 팔 방향과 누적 비교하므로 작은 프레임별 변화가 쌓이면 반영한다. 실제 손·팔 관측이 멈추면 현재 검 각도를 유지한다. 정지한 손에 자동 회전, 리듬 흔들림, 잔여 easing 복귀를 만들지 않는다. 팔이 신뢰할 수 있게 방향을 바꾼 경우는 손목 위치가 같아도 현재 검 각도에 반영할 수 있지만, 손 이동 없는 회전만으로 스윙 잔상을 추가하지 않는다.

각 trail은 관측 시점의 각도를 저장한다. 렌더러는 그 각도로 검의 바닥점을 구해 이전/현재 검 사이의 면과 회전된 검 전체 잔상을 그린다. 새 프레임을 가짜 관측으로 삽입하지 않는다. reduced에서는 잔상을 모두 생략하고 현재 실제 장식 각도는 유지한다. low는 기존 최대2개, high는 최대6개의 검 잔상을 그대로 사용한다. 관측 trail은 기존 최대18개/0.22초, renderer 방어 상한은 기존20개다. 리본도 기존 인접 trail loop 하나로 그리며 별도 무한 입자/시간 루프가 없다.

`bladeGeometry(x,y,cell,hand,bladeAngle)`는 언제나 tip `{x,y}`를 그대로 돌려준다. 길이는 기존 `hypot(.20,.65)*cell`, 바닥은 `{x-sin(angle)*length,y+cos(angle)*length}`다. 4×3 판정면·`planeRect`·grid/stage 변환·플레이어별 clip을 변경하지 않았다. 렌더러에 각도 필드가 없는 이전 형식의 손/잔상을 전달해도 기존 좌우 기울기로 표시한다.

## 가림과 시간 경계

기존 손 추적 reset에 현재 장식 각도와 마지막 채택 팔 각도를 함께 초기화한다. 손 가림/유효하지 않은 관측, input epoch·session·source·player·hand 변경, seek/정지 시계, .2초 초과 간격, 불가능하게 큰 속도에서 예전 각도와 잔상이 이어지지 않는다. 재인식 첫 샘플은 새 팔 방향 또는 기본 기울기에서 시작하고 이전 trail은 없다. 팔꿈치만 가려지고 손목은 유효하면 실제 손 이동에 따라 표시하거나 정지 각도를 유지하며, 손목 인식/판정 자체를 불필요하게 끊지 않는다.

## 남은 실제 검증과 한계

팔꿈치와 손목만 사용하는 2D 화면 연출이다. 실제 손가락/손잡이 쥐기/회내·회외/3D 검 방향을 측정하지 않는다. 카메라 가까이 뻗은 팔처럼 화면상 팔 길이가 짧거나 가려진 경우에는 손 이동 기반 표시로 낮춰 동작한다. 실제 두 사람의 조명·카메라 FPS·가림 환경에서 자연스러움 검증은 별도다. 고정 판정점을 지키기 위해 장갑 그림은 실제 손목보다 검 몸체 쪽에 있으므로 그 장갑을 실제 추적 손 위치로 안내하지 않는다. 별도 튜토리얼/제품 안내의 통합은 종합기획 담당 영역이다.

AI 검색어: wrist anchored decorative saber, elbow wrist aspect corrected angle, shortest angle interpolation, bounded angular velocity, observation driven saber trail, stationary input no procedural swing.
