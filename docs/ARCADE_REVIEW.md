## 효과음의 실제 브라우저 PCM 비교

검토엔진이 별도 `arcade-review` 세션에서 `agent-browser`로 직접 실행했다. 스피커로 듣는 시험은 하지 않았다. 변경 전 소스는 기존 `tests/browser-feedback-mix.js`로 측정했고 변경 후에는 새 모듈을 새 query로 import해 이전 모듈 캐시와 분리했다.

동일 조건은 OfflineAudioContext 48,000Hz·스테레오·1초다. 5등급×1/8중첩×볼륨0.75/1의20조건을 렌더하고, 별도로50ms에서 stop하여80ms 이후 표본이0인지를 확인했다. 21조건 모두 유한 PCM·peak<1·중단 후 정리를 통과했다.

| 효과음 조건 | peak 범위 | RMS 범위 |
|---|---:|---:|
| 변경 전, 볼륨1, 단일 | 0.1817914~0.2116228 | 0.0075831~0.0088085 |
| 변경 전, 볼륨1, 8중첩 | 0.5141838~0.5985597 | 0.0214482~0.0249143 |
| 변경 후, 볼륨0.75, 단일 | 0.3684447~0.4579780 | 0.0141061~0.0166775 |

같은 등급·볼륨1의 단일 RMS는 이전보다 약2.4~2.5배였다. 이는 디지털 신호 에너지의 비교이며 사람에게 정확히 그 배수로 크게 들린다는 의미가 아니다. 최대 관측 피크는0.7472112였다. WaveShaper의 명목 상한만 보고 클리핑을 추정하지 않고 oversampling 뒤 실제 출력도 측정했다.

중단 시험은 렌더를50ms에서 suspend하고 `feedback.stop()` 후 resume했다.80ms 이후 peak는 정확히0, nodes/bursts는0, master는null이었다. 오래된 콜백이 새 limiter를 끊지 않는 검사는 별도 순수 회귀로 통과했다. 음악+칭찬까지 합친 최대 믹스 음량, 총성풍 음색의 만족도, 실제 출력 장치의 체감은 별도다.

## 긴 음악의 독립 브라우저 경계 확인

브라우저 메모리에 **181초·8kHz·16bit mono WAV, 2,896,044 bytes**를 만들어 실제 File 입력에 넣었다. 사용자 파일을 읽거나 디스크에 음원을 저장하지 않았다. 이후 실제 시작 버튼을 눌러 재생하고 끝부분으로 seek했다. 전체181초를 실시간 청취한 시험은 아니다.

- 네이티브 Audio의 원본 길이181초, 게임 진행 최대150초, 안내 `원곡03:01 중 앞 구간` 확인.
- 게임 최종 정지 시각 **150.003846초**, 음악 paused.350ms 더 기다려도 원곡 뒤구간으로 진행하지 않았다.
- 결과 안내는 `독립 긴 노래181초 · 02:30`, 원본 채보 마지막 노트는148.928571초였다.
- 편집기의 별도 네이티브 Audio는 **정확히150초**에 정지했다. 반복 구간148~149초에서150.1초 timeupdate를 보내면148초로 복귀했다.

초기 검토 스크립트에서 존재하지 않는 dialog class를 골랐고, 다음 시도는 '현재 JSON 보기'를 누르기 전 빈 텍스트를 파싱했다. 두 실패는 하네스 오류였다. 실제 id/표시 절차로 고친 뒤 위 경계를 끝까지 확인했으며 앱 오류로 분류하지 않는다. 이 시험에는 실제 카메라·사람 손 입력을 사용하지 않았다.

## 실제 바로가기와 서버 식별

바탕화면의 실제 `.lnk`를 WScript.Shell로 읽어 다음을 확인했다. 바로가기 생성·클릭 자체는 생성엔진이 수행했다.

- 파일: `C:\Users\Microsoft\Desktop\얼마루 비전.lnk`
- 대상: `C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe`
- 인수: `-NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "D:\3_GosranAI\8.visiongame\eolmaru-vision-game\tools\launch.ps1"`
- 작업 폴더: `D:\3_GosranAI\8.visiongame\eolmaru-vision-game`
- 아이콘: 같은 저장소의 `public\assets\eolmaru-vision.ico,0`. 대상/작업 폴더/아이콘 모두 존재했다.

독립 자동 검사에서 같은 앱 표식을 내지만 다른 프로젝트 root인 가짜 서버를 임의 포트에 열었다. 런처는 identity와 nonce 증명을 시도한 뒤 이를 거절했고 가짜 서버는 계속 살아 있었다. nonce 임시파일은 남지 않았다. 실제 프로젝트 서버를 별도 포트에서 실행한 경우 정확한 root/version/serverHash와 identity의 no-store·페이지의 no-cache를 확인하고 **Reused=True, Restarted=False**, 같은 프로세스 생존을 확인했다. 다른 서버를 종료하지 않았다.

추가로 서버가 없는 빈 포트에서 실제 `launch.ps1 -NoBrowser -Port`만 실행했다. 런처가 새 Node 서버를 기동해 **Reused=False, Restarted=False**, 현재 root/serverHash와 version/launch URL을 반환하는 경로도 직접 확인했다. 종료 시 이 실행이 만든 PID, 해당 포트 소유 PID, node.exe 이름, 정확한 server.mjs 명령행을 모두 대조한 뒤 그 PID만 정리했다. 이 단독 검사는1/1,5321.3071ms였으며 이후 전체 회귀에 포함했다.

초기 Node 자식 powershell.exe는 Codex의 PowerShell7 모듈 경로를 상속해 Windows PowerShell5.1에서 Get-FileHash를 찾지 못했다. 셸에서 직접 실행한 Windows PowerShell은 정상이라 이를 '실제 바탕화면 실행 실패'로 단정한 첫 보고를 정정했다. 생성엔진이 두 ps1에 해당 `$PSHOME\Modules`를 앞에 두도록 보완한 뒤 **테스트 환경을 정리하지 않은 원래 Node 자식 조건에서16/16 통과**했다. BOM은 유지한다. 시스템/사용자 전역 모듈 경로를 변경한 것은 아니다.

생성엔진은 동일 폴더의 legacy 서버를 nonce와 프로세스 확인 후 재시작하고 identity0.7.0을 확인했다고 보고했다. 실제 `.lnk` 실행 뒤 새 Chrome URL의0.7.0/launch 값과 화면 footer0.7.0도 확인했다고 보고했다. 검토엔진이 그 클릭을 다시 실행했다고 주장하지 않는다. 바로가기의 한글 파일 이름은 직접 확인했지만, 프로젝트 폴더 자체를 새 한글 경로로 복사한 시험은 하지 않았다.

## 생성엔진·시각 담당의 추가 증거와 한계

생성엔진은 browser-arcade22개(241초 WAV의 앞150초·편집/loop·잘못된 파일 원자성·취소·이미지1회·외부0), 기존 music31개와 editor27개, 배경8개와 새로고침 뒤 배경정지 저장 복원1개를 새 코드에서 통과했다고 보고했다. 합계 **브라우저89조건**이며 검토엔진의181초 독립 경계·PCM21조건과 구분한다. 최종 자산 감사는104파일·56,768,225bytes·누락/중복/외부참조0으로 보고됐다.

시각 담당의 이미지 출처·해시·프롬프트·투명도·장면 캡처는 [DANCE_ART](DANCE_ART.md)에 있다. 검토엔진은 최종 두 PNG를 직접 보았고, 요청당 한 번 준비·최대 두 drawImage·low 렌더 축소를 독립 검사했다. 장면별 CPU 시간은 시각 담당의 합성 장면 계측이며 실제 카메라 성능으로 바꾸어 표시하지 않는다.

최종 수락표는 [ARCADE_PLAN](ARCADE_PLAN.md)을 따른다. 사람 청취·배경 취향·실제1/2인 카메라·낮은 빈도의 마우스/터치패드 체감은 대기다. 출처 불명의 총성 샘플, 온라인 합성, 자동 Git 갱신, 사용자 원곡 수정/전송, 새 의료 정확도 주장은 추가하지 않았다.
