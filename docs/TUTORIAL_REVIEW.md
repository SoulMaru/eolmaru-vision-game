# 0.8 독립 검토 — 튜토리얼·팔 회전·베이스

검토엔진은 시작 시 clean `241c02a`를 확인했다. 이 문서와 `tests/review-tutorial.test.mjs`만 작성한다. 앱 소스 수정·커밋은 하지 않는다. 이전 0.7의 148개 통과는 기준 이력이며, 이번 0.8의 최종 회귀 결과와 구별한다.

현재 상태: **독립 코드·자동 검사·음원 출력·선택곡 보존 검토 완료**. 검토 중 발견한 TR01~04는 수정 뒤 검사했다. 전체 시각/성공 실습의 생성엔진 브라우저 증거는 해당 엔진의 최종 기록과 구별한다. 실제 사람 카메라·2인 신체 인식·스피커 청취를 검증했다는 뜻이 아니다.

## 독립 수락 조건

- 별도 튜토리얼은 자리·5초 범위·양손·방향·타이밍·계속 베기·곡 선택의 7단계다. 실습은 실제 성공 또는 명시적 건너뛰기 뒤 진행한다.
- P1/P2의 관측·성공·건너뛰기는 따로 기록한다. 마우스 실습이나 무검출 상태를 카메라 위치·범위 검증으로 표시하지 않는다.
- 뒤로·다시·인원/입력 변경·닫기·카메라 소실·루프 재시작은 이전 궤적을 이어 가짜 성공을 만들지 않는다. 선택곡·편집 원본·긴 노래의 150초 구간을 튜토리얼이 덮어쓰지 않는다.
- 회전은 그림의 변화다. 손목의 밝은 끝 좌표·시간·이동량·충돌 판정은 동일하다. 팔꿈치 가림·낮은 신뢰도·±π 경계·정지·복귀를 확인한다.
- 베이스는 1·2 / 3 / 4·5등급의 세 음색이며 정확도 증가에 따라 커진다. 기존 3개 소스, 최대 8개 중첩, 공유 리미터, 중단 정리 계약을 유지한다.
- 음악 12곡·음성 36개·메타 14개의 기존 바이트 보존 검사와 기존 148개 회귀 기대를 완화하지 않는다.

## 자동 검사 결과

검토엔진 직접 실행 이력:

- 첫 20개: 18 통과 / 2 실패. TR01의 자리 확인 시간 경계를 드러냈다.
- 범위·비동기 수명 검사 추가 시 25개: 22 통과 / 3 실패. TR02 두 재현과 TR04 한 재현이었다.
- 수정 후 `npm test`: **173/173 통과**, 실패/건너뜀 **0**, 7730.0846ms. 기존 148개와 당시 신규 25개를 함께 실행했다.
- 이어 TR03 인원 변경 직접 회귀 1개를 추가한 `node --test tests/review-tutorial.test.mjs`: **26/26 통과**, 실패/건너뜀 **0**, 125.3884ms. 현재 저장된 검사 총수는 **174개**다. 이 마지막 1개 추가 이후의 전체 실행은 생성엔진 최종 기록과 구별한다.

베이스 매핑·연속 gain·invalid 입력, 손끝 불변·종횡비/해부학 손·각속도/±π/정지/소실, 같은 궤적의 동일 판정, 7단계 채보 범위, 2인 실습/건너뛰기/보고 복사/재시도, 실제 `SaberGame` 보정 콜백, 제어 가능한 DOM/Audio 경계의 비동기 준비/닫기/루프/인원 변경을 검사한다. mock 검사는 사람 카메라나 실제 출력 증거로 사용하지 않는다.

기존 보정 성공 fixture는 생성엔진이 양손의 이동 표본에 `hand`만 명시해 새 계약과 일치시켰다. 기존 보정 cell `.2`·중앙 `.6`·고정 좌표의 기대는 그대로다. 기존 148개 판정/입력/오디오 제한 기대를 낮추지 않았다. 음악 12곡·음성 36개·메타 14개의 전체 보존 해시 검사도 이번 전체 실행에서 통과했다.

## 독립 실제 PCM 측정

검토엔진이 별도 Chromium `tutorial-review` 세션에서 로컬 `src/saber-feedback.mjs`를 가져와 **실제 `OfflineAudioContext`**로 렌더했다. `state` getter만 `running`으로 노출해 스케줄 허용 조건을 충족했으며, 오실레이터·필터·팬·리미터 계산과 PCM은 브라우저 엔진이 수행했다. 음성은 끄고 효과음만 측정했다.

측정 시각: `2026-09-27T10:33:18.062Z`. 44.1/48kHz × 음량 .75/1 × 동시 1/8개 × 정확도 15지점 = **120개, 각 2채널 1초**. 정확도는 `0,10,19.999999,20,30,39.999999,40,50,59.999999,60,70,79.999999,80,90,100`이다. 등급은 `min(4,floor(accuracy/20))`로 실제 경계와 일치시켰다. 같은 플레이어·같은 손에 중첩해 출력이 같은 채널로 겹치게 했다.

| 음량 | 중첩 | 두 샘플률 전체 peak 범위 | 1초 RMS 범위 |
|---|---:|---:|---:|
| .75 | 1 | .1327612–.3158525 | .0118532–.0299169 |
| .75 | 8 | .3529879–.6621745 | .0327804–.0749782 |
| 1 | 1 | .1757549–.4043937 | .0157635–.0392603 |
| 1 | 8 | .4473689–.7341862 | .0428979–.0923217 |

- 모든 PCM 유한값, 전체 최대 peak **.7341862 < 1**. 40·60% 음색 전환을 포함해 RMS가 증가한다.
- 최초 비교 허용 `1e-10`에서는 44.1kHz/.75/8개 조건의 19.999999→20% RMS가 **1.91e-10** 낮아졌다고 나왔다. 같은 음색의 거의 동일 gain을 Float32로 계산한 반올림 크기다. 따라서 PCM 단조 비교 허용을 **1e-8**로 명시한다. gain 자체의 단조성은 독립 순수 검사로 엄격히 검사한다. 40·60% 음색 경계의 실제 증가는 이 오차보다 충분히 크다.
- 별도 8개/음량1/48kHz 렌더를 50ms에서 정지해 `feedback.stop()`을 호출한 뒤 재개했다. 100ms 이후 tail peak **0**, nodes/bursts **0**, master **null**이었다.
- 이는 디지털 효과음 출력 검증이다. 실제 스피커 음량·음색 선호·사람 청취·음악과 칭찬 음성을 합친 전체 믹스의 최대치는 별도 미검증이다.

재현 방법: 실제 Chromium에서 로컬 모듈을 import하고 각 조건마다 새 `OfflineAudioContext(2,sampleRate,sampleRate)`와 새 `SaberFeedback`을 만든다. `voiceEnabled:()=>false`, 지정 `effectVolume`으로 `hit`을 고유 ID로 1회 또는 8회 호출한다. `startRendering()`의 두 채널 전 표본에서 peak와 `sqrt(sum(x*x)/(2*sampleRate))`를 계산한다. stop 검사는 `suspend(.05)` 후 `stop()`→`resume()` 순서로 수행한다. 네트워크 음원이나 운영체제 오디오 녹음은 사용하지 않는다.

## 독립 실제 앱 연결 확인

검토엔진의 별도 Chromium 세션에서 `2026-09-27T10:43:48.992Z`에 **15조건 통과**했다. 실제 로컬 HTML·앱·File input·오디오·편집기를 사용했다. 이 확인은 TR02~04의 마지막 수정 직전이며, 마지막 변경의 수명/인원/보정 경계는 위의 수정 후 자동 검사로 확인했다.

1. 메모리에서 생성한 181초 WAV가 일반 리듬의 150초 구간으로 적용된다.
2. 별도 튜토리얼 카테고리는 자리 단계로 열린다.
3. 포인터 체험의 자리는 카메라 확인이 아니라고 표시한다.
4. 범위 단계는 실제 손 범위 보정을 생략했다고 표시한다.
5. 양손 실습 성공이 없으면 다음이 잠겨 있다.
6. 튜토리얼의 별도 로컬 Audio 시계가 실제로 증가하며 일반 음악은 정지한다.
7. 일시정지 뒤 연습 시계가 고정된다.
8. 인원을 2명으로 바꾸면 첫 단계에서 두 사람의 새 기록으로 시작한다.
9. P1/P2 양손 실습 미완료는 다음을 열지 않는다.
10. 명시적 건너뛰기는 방향 단계로 이동한다.
11. 뒤로는 양손 단계로 돌아가 미완료 상태를 유지한다.
12. 나가기는 일반 리듬으로 복귀하고 연습 Audio의 src를 해제한다.
13. 이전 일반 음악의 동일 Blob URL·제목·BPM140·150초 구간이 보존된다.
14. 튜토리얼 전 적용한 사용자 2노트 채보 JSON이 편집기에서 완전히 동일하다.
15. 런타임 외부 resource 요청은 **0**이다.

이 시험에서 카메라는 열지 않았고 손동작 성공은 대신 주입하지 않았다. 성공 기준은 독립 자동 판정 검사와 생성엔진의 별도 실제 UI 실습 시험으로 구별한다. WAV는 메모리로만 생성했으며 사용자 파일을 업로드하거나 음악 원본을 바꾸지 않았다.

## 남은 실사용 확인

실제 사람의 카메라 위치/양손 범위 확인, 팔 회전의 체감 안정성, 실제 2인 인식 성능, 3종 베이스의 사람 청취·취향·스피커 저음 재현은 미검증이다. 디지털 RMS 증가를 지각 음량의 보증으로 표현하지 않는다. 최종 자산 감사와 일반 플레이·전신 세트·편집기의 전체 브라우저 회귀는 생성엔진의 이번 0.8 실행 기록을 참고한다. 알려진 독립 검토 차단 문제는 남아 있지 않다.
