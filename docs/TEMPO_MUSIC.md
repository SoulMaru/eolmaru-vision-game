## 박자와 길이

음악 길이는 `마디 수 × 4 × 60 / BPM`이다. 킥과 합성 이벤트는 `n × 60 / BPM` 시각에 배치하고 마지막에 한 번만 정수 오디오 표본으로 반올림한다. 최대 이벤트 시각 반올림은 `0.5 / 44100`초, 약 0.0114ms다. `timing.firstEightKickSeconds`와 `firstEightKickSamples`에 첫 여덟 박의 배치값을 기록했다. 이는 생성 시계의 증거이며 녹음에서 박자를 자동 추정했다는 뜻이 아니다.

`durationSeconds`는 정확한 마디 공식의 값이고, `duration`은 배포 Ogg를 ffprobe로 읽은 값이다. `decodedFrames / sampleRate`는 전체 디코드한 표본 길이다. 정수 표본과 Ogg의 마지막 타임스탬프 때문에 한두 표본 정도의 차이가 날 수 있으므로 셋을 혼동하지 않는다. 채보 시작 오프셋은 모두 0초다.

## 제작과 검증 방법

새 제작기는 `tools/music-training-compose.py`다. 검토된 기존 제작기에서 F 모티프 추출과 FFmpeg 계측 함수를 읽어 재사용해 동일 작업을 중복 구현하지 않았다. 음악 합성과 편곡 데이터는 새 제작기에 있다.

1. 기존 `public/audio` 파일의 SHA-256 목록을 합성 전에 읽는다. 이번 일곱 신규 ID만 보존 비교에서 제외한다.
2. 각 곡을 임시 폴더에 합성하고, DC 제거·완만한 포화·원음 피크 0.78 조정을 거친다.
3. 두 번 측정하는 FFmpeg loudnorm으로 목표 -14 LUFS / -2 dBTP / LRA 9를 적용한다. 44.1kHz와 정확한 표본 수, 연속 타임스탬프를 명시한다.
4. Vorbis quality 5로 변환한 **최종 Ogg 전체**를 float PCM으로 다시 디코드한다. 길이·코덱·스테레오·표본 수·피크·RMS·LUFS·true peak·파일 크기·SHA-256을 측정한다.
5. 길이·클리핑 방지·음량 검사와 기존 파일 보존 검사를 모두 통과한 곡만 `public/audio`에 복사한다. 임시 WAV·Ogg는 자동 정리한다.

음원 수치는 디지털 신호 검사다. **실제 사람 청취, 음색 취향, 스피커·헤드폰 재생, 카메라 손 동작과의 체감 동기는 미검증**이다. 코드의 필터와 음량 상한은 귀의 피로가 없다는 보장이 아니다.

## 재현

```powershell
python tools/music-training-compose.py --track all --f-engine 'F:\0.SoulmaruAI\1.aiimage\webtoon-translator\local-api\backend\python\video\webtoon.py'
```

한 곡만 만들려면 `--track 80`, `--track 90` 등 원하는 BPM을 지정한다. `--f-engine`을 빼면 새 주 훅 일부를 이용한 독립 인트로로 바뀌며 메타데이터가 그 경로를 구별한다. 배포된 F 모티프 버전과 동일하다고 표시하지 않는다.

동일한 합성기·NumPy·F 함수·시드는 같은 원음 합성을 재현하기 위한 조건이다. Ogg 컨테이너 일련번호나 인코더 버전이 달라지면 재생 내용이 같아도 배포 바이트 SHA-256은 달라질 수 있다. 원음 비교용 `masterPcmSha256`도 별도로 제공한다.
