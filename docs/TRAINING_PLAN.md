## 확정 범위

- **80 / 90 / 100 / 110 / 120 / 130 / 140 BPM의 독립 창작곡7개**를 추가한다. 각120~180초, 테크노/댄스 성향이며 BPM만 바꾼 기존 음원의 복사본으로 제공하지 않는다. 동일 편곡기의 재사용은 가능하되 곡별 작곡 설정·시드·멜로디/음색/편곡·메타데이터를 남긴다. F 제작소 원본은 수정하지 않는다.
- 손 리듬에서 곡을 선택해 **한 곡 진행 후 종료**한다.7곡 자동 연속 코스·강제 순서·레벨 잠금·점수 보상은 추가하지 않는다. 기존 손 리듬3곡과 합쳐 선택10곡, 전체 음원은 기존5+신규7=12곡이다. 내 컴퓨터의 노래 선택도 보존한다.
- **타겟 접근 속도0.6~1.6배(0.1단위)**와 **출현 간격 최소2박/최소4박**은 별도 조작이다. 접근 속도는 미리 보이는 시간을 바꾸고, 출현 간격은 노트 밀도를 바꾼다. 음악 재생 속도·음높이·BPM을 변속하지 않는다. 기본 접근1.0배·간격2박이다.
- 타겟은 기존 **한 번 베기**와 신규 **계속 베기** 두 종류다. 새7곡에는2~4박짜리 계속 베기를 곡별8~14개 배치한다. 편집/import 규격은0.5~6초를 허용한다. 같은 손을 움직이며 가만히 대고 있기만 해서는 성공하지 않는다. ∞·계속 베기 문구·남은 초·시간 고리·초록 이동 막대로 구별한다.
- 기존 음악5곡/메타·36음성/원고·225초 전신 서기/바닥/커플·최대2인·무료 로컬·무탈락·왼쪽 메뉴·실제 전체화면을 보존한다. 음성 재생성이나 새 건강 정확도 주장은 이번 범위가 아니다.

## 확정된 구현 계약

### 곡 길이와 접근 속도

`src/songs.mjs`와 신규7개 메타데이터를 직접 대조했다. 아래 길이는4/4 박자 구조의 길이를 소수점3자리로 표시한다. 제작 담당과 독립 검토엔진이7곡 전체 디코드를 각각 확인했으며, ffprobe 측정값·음량·해시·제작 경로는 [TEMPO_MUSIC](TEMPO_MUSIC.md)에 있다. 계획 시계·Ogg 타임스탬프·정수 PCM 표본 길이는 허용 오차 안에서 구별한다.

접근 시간은 `leadSeconds = 1.8초 / 접근 배수`, `spawnTime = max(0, hitTime − leadSeconds)`다.0.6배는최대3초,1.0배는최대1.8초,1.6배는최대1.125초로 미리 보인다. 곡 맨 앞 노트는0초 클램프 때문에 실제 예고 시간이 짧을 수 있다. `hitTime`과 오디오 `currentTime`은 변하지 않고 `playbackRate`는1을 유지한다. 빠른 접근의 낮은 인식률·실제 난도는 카메라 실기에서 별도 확인한다.

옵션은 시작 전에 변경·저장하고 재생·일시정지·곡/채보 로딩 중에는 잠근다. **원본 `chart`는 불변이며 `playChart`만 파생**한다.2박 설정은 원본 전체,4박 설정은 시각 묶음의0,2,4…번째만 남겨 최소4박 간격을 만든다. 양손 동시 묶음은 함께 유지/제외하므로 한 손만 떨어지지 않는다. 원본 간격이 불규칙하거나 지속 타겟의 여유가 있으면4박보다 넓어질 수 있다.

이 실행용 설정은 기본곡·연습곡·사용자 import/편집 채보 모두에 적용한다. 편집기가 열고 JSON으로 저장하는 것은 항상 원본 전체이며,4박에서 숨긴 노트를 삭제하지 않는다. 첫 권고의 '사용자 채보에는 밀도 적용 제한'은 이 비파괴 실행용 파생 방식으로 대체했다. 비동기 로딩은 기존 세대/곡 검사를 유지한다.

### 계속 베기: 이동 시간과 최종 결과

아래는 `saber-core.mjs`의 저장된 구현을 대조한 정책이다. 순수 판정 코드를 읽은 사실과 독립 실행 통과는 구별한다.

1. 지속 타겟은 `cutDirection:'any'`이며 같은 손의 왕복/다방향 움직임을 허용한다. 판정 영역은 중심에서가로/세로 각각±0.55칸이다. 최초 유효 교차 시각을 저장하며, 초기 권고와 달리 시작±250ms 안에 진입해야만 지속 누적이 가능한 구조는 아니다. 이른 진입은 `hitTime−0.25초`부터 고려하고 실제 이동 누적은 `hitTime`부터 `endTime = hitTime + durationSeconds`까지 잘라 계산한다.
2. 유효 이동 속도는0.65칸/초 이상, 최대35칸/초이며 표본 공백은0.2초 이하다. 신뢰도0.55~1·좌표/시각 유한성·같은 사람/손/소스/입력 epoch·실시간과 음악시각 간격 차이 등을 검증한다. 공간 교차와 음악 활성 기간에 걸친 **이동 시간의 합집합**을 누적하므로 가만히 있음·영역 밖·정지·연결이 끊긴 표본·다른 손/사람은 진행률을 늘리지 않는다.
3. 전체 지정 기간의 **60% 이상 유효 이동**과 **마지막25% 시간 구간 안의 유효 이동**이 모두 있어야 성공한다. 마지막 구간 전체를 채워야 한다는 뜻은 아니다. 겹친 시간 구간을 중복 합산하지 않는다. 실패 시 별도 관측 시간 비율이80% 이상이면 `miss`, 미달이면 `untracked`로 구별하며 둘 다 탈락이나 성공 칭찬이 없다.
4. `time >= endTime`에서 이동 조건을 이미 충족했으면 **종료 박자에 바로 성공**한다. `endTime` 전에는60%를 채워도 성공하지 않는다. 미충족일 때만 `endTime + 0.45초`까지 늦은 표본을 기다리고, 이후에도 부족하면 관측량에 따라 실패를 분류한다. 최초 설계의 무조건0.45초 성공 지연은 폐기했다. 플레이어별 최종 결과는 한 번이며 시작·진행 프레임마다 성공어/폭죽을 반복하지 않는다.
5. **교차 타이밍 정확도**는 최초 유효 교차 시각으로 기존 식/5등급을 계산한다. 초기 진입이±250ms 밖이면 정확도는0으로 제한되지만 지속 성공 자체는 이동 조건을 따른다. `sustainAccuracy`는 별도 이동 시간 비율이다. 지속 최종 성공 때만 최초 타이밍 등급/성공어를1회 전달한다.
6. 일시정지/버퍼 대기 동안 음악 시각과 이동 누적은 증가하지 않는다. 재개 시 입력 epoch를 끊되 정지 전 누적 진행은 유지한다. seek는 진행을 초기화하고 이미 시작된 지속 타겟을 `skipped`로 처리해 가짜 성공을 만들지 않는다. 새 곡/새 세션은 초기화하며 마지막 타겟에는 곡 끝 여유가 있어 최종 결과를 한 번 정리할 수 있다.

지속 타겟 이후 **같은 손 또는 같은 칸**의 다음 타겟은 `endTime + 0.5초` 이상이어야 한다. 검증기와 생성기에서 여유를 확보하며 다른 손/다른 칸의 동시 노트는 기존 최대2개 규칙을 따른다. 지속 누적은 일반 타겟의 `usedStrokes` 검사보다 먼저 별도 수행한다. 일반 타겟의 한 베기당 한 번 소비 규칙은 그대로다.

### v1 채보 호환과 편집기

`schemaVersion:1`을 유지하고 선택적인 `kind`/`durationSeconds`를 추가한다. 필드가 없거나 `kind:'tap'`이면 일반 타겟이며 `durationSeconds`를 넣으면 거절한다. `kind:'sustain'`은 자유 방향·유한한0.5~6초 길이만 허용한다. 새7곡의 생성 규칙2~4박과 편집/import 허용 범위0.5~6초는 구별한다. 알 수 없는 타입·음수/0/비수치 길이·곡 밖 종료·같은 손/칸 간격 위반은 거절하며 지속 종료 뒤에도 곡 끝1초 여유를 요구한다.

편집기는 타입 선택과 '계속 베기 초 · 0.5~6' 입력을 제공한다. 지속 타입 선택 시 방향을자유로 고정하고 원본의 타입/길이를 열기·적용·JSON·undo에 보존한다. 일반 노트 JSON에는 불필요한 새 필드를 강제로 추가하지 않는다. 잘못된 파일은 현재 곡·채보·편집 초안을 보존한다. 접근/간격 옵션은 편집하거나 저장하는 원본에 반영하지 않는다.

### UI 문구와 기존 모드 대조

왼쪽 슬라이더는 '타겟 접근 속도'와배수, 간격은 '기본 · 최소2박 / 여유롭게 · 최소4박', 도움말은 음악 속도가 바뀌지 않음을 표시한다. ∞ 타겟의 초록 막대는 `이동비율/0.6`을1로 제한해 필요한 이동량을 나타내고 바깥 고리는 경과시간을 나타낸다. **막대가 찼다고 즉시 성공한 것은 아니며 마지막 구간에서도 움직여야 한다.** 카메라/점수 정확도와 혼동하지 않는다.
