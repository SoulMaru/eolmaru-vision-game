## 원하는 완성 모습

노래 선택 → 1인 또는 2인 선택 → 카메라와 양손 위치 맞추기 → 시작과 전체 화면 → 앞으로 다가오는 블록을 손으로 위·아래·좌·우로 베기 → 한 곡 종료.

의자에 앉아서 손으로만 조작한다. 왼손은 빨강과 L 표시, 오른손은 파랑과 R 표시인 가상 세이버를 사용한다. 최대 2인이므로 세이버는 최대 4개다. 블록의 손 표시와 화살표를 보고 해당 손을 그 방향으로 움직인다. 자유 방향 블록도 지원한다. 놓쳐도 음악은 계속된다.

**여기서 1인·최대 2인은 플레이어 수다.** 개발자 수는 제한하지 않는다. 혼자 만들면 아래 순서대로 진행하고, 개발자 둘이 작업한다면 A는 입력·판정·음악 시계, B는 화면·채보·아트·검증을 맡되 공용 파일의 동시 수정을 피한다.

Beat Saber의 접근 블록·양손 구분·방향 베기 원리를 참고하는 창작 게임이다. 원작 이름을 제품명으로 사용하거나 로고·음악·채보·그래픽을 복사하지 않는다. 제품 작업명은 **얼마루 비전 세이버**다.

## 2단계 — 음악 시계·JSON 채보·접근 블록

```text
[목표]
음악 재생 시간에 맞춰 4×3 레인의 블록이 플레이어 쪽으로 접근하게 하라.

[요구사항]
1. 아래 문서의 v1 JSON 채보 계약을 구현한다. time은 초, lineIndex는 0~3, lineLayer는 0~2다.
2. 노트에는 고유 id, time, lineIndex, lineLayer, hand(left/right), cutDirection(up/down/left/right/any)가 있다.
   표시 색상은 hand에서 파생한다. 색상과 손을 별도로 저장해 불일치하는 구조는 피한다.
3. 음악 audio.currentTime을 기준으로 계산한다. 프레임마다 speed를 더해 위치를 누적하지 않는다.
   hitAudioTime = note.time + chart.offsetSeconds
   spawnAudioTime = hitAudioTime - leadSeconds
   z = speed * (hitAudioTime - audio.currentTime), 판정 평면은 z=0이다.
4. 약 1.8초의 접근 시간을 시작값으로 쓰고 조절 가능하게 한다. 이는 확정 최적값이 아니라 설계 초기값이다.
   v1은 spawnAudioTime이 음수인 채보를 거절한다. 필요하면 작성자가 첫 노트 시각을 늦춘다.
   음악이 0초에 멈춘 카운트다운을 늘리는 것으로 음수 음악 시각을 만들 수 있다고 가정하지 않는다.
5. 새로 시작/정지/재개/시간 이동 시 현재 음악 시각으로 활성 노트 범위를 복원한다.
   지나간 모든 블록을 한꺼번에 생성하거나 효과음을 몰아서 실행하지 않는다.
6. 150초 기존 창작곡 한 곡에 손이 가슴 주변에서 닿는 쉬운 채보를 작성한다.
   노트 묶음 사이 최소 2박, 왼손/오른손 교대, 필요한 되돌림 시간을 둔다.
   hitAudioTime은 0 이상 duration-1초 이하여야 하며 spawnAudioTime도 0 이상이어야 한다.
   원본 note.time과 offset 적용 후 시각을 모두 검증해 접근 시간과 마지막 판정/효과 여유를 확보한다.
7. 노트 중복 ID, 잘못된 열/층/방향/손, 비수치/무한 시각, 곡 밖 시각, 같은 자리를 차지하는 충돌 노트를 검증한다.
   JSON 루트/배열 형식과 schemaVersion을 확인하고 v1은 일정 BPM만 지원한다.
8. 시간 정렬은 원본을 변형하지 않는 복사본으로 하며 최대 1MB/2000노트 제한을 시작 정책으로 둔다.
   제한이 바뀌면 이유와 검사 근거를 남긴다. 음원 경로는 앱의 허용 목록만 사용한다.
9. BPM은 기존 범위 40~240의 유한수, offset은 유한수, 열/층은 정수인지 검사한다.
   time은 초 단위를 유지하되 검증 시 마이크로초 정수로 정규화한다.
   같은 정규화 시각만 동시 묶음으로 본다. 묶음당 최대 2개이며 서로 다른 손·칸이어야 한다.
   서로 다른 묶음 간격은 최소 2박이다. 정밀도 반올림 오차 1마이크로초만 허용한다.
   양손의 빠른 교대로 이 간격을 우회할 수 없게 한다. 위반 채보는 이유를 알린다.
   검증을 전부 통과한 뒤 곡/채보를 한 번에 적용한다. 실패하면 기존 곡과 세션을 보존한다.
   JSON의 외부 URL, 임의 HTML, 실행 지시는 실행하지 않는다.

[완료 조건]
10초/60초/곡 끝에서 블록이 예정된 음악 시각에 판정선에 도달한다.
느린 렌더링에서도 도달 시각이 누적해서 밀리지 않는다.
잘못된 JSON을 읽어도 앱이 멈추지 않고 원인을 한국어로 알려준다.
```

### v1 채보 계약 — 2·3·8단계 공용

```json
{
  "schemaVersion": 1,
  "songId": "maru-flow",
  "bpm": 112,
  "offsetSeconds": 0,
  "notes": [
    { "id": "n001", "time": 4.285714, "lineIndex": 1, "lineLayer": 1, "hand": "left", "cutDirection": "down" },
    { "id": "n002", "time": 5.357143, "lineIndex": 2, "lineLayer": 1, "hand": "right", "cutDirection": "up" },
    { "id": "n003", "time": 6.428571, "lineIndex": 1, "lineLayer": 0, "hand": "left", "cutDirection": "any" }
  ]
}
```

이는 3개 노트의 **형식 예시**이며 완성된 한 곡 채보가 아니다. `lineIndex=0`은 플레이어 자기 무대의 화면 왼쪽, `lineLayer=0`은 위쪽이다. `cutDirection`은 화면에서 손이 이동하는 방향이다. `hand`는 사람 자신의 해부학적 손이다. 거울 화면이나 왼쪽/오른쪽 플레이어가 바뀌어도 손 ID 자체를 교환하지 않는다.

`time`은 오프셋이 적용되기 전 채보 시각이다. `offsetSeconds=+0.10`이면 모든 목표가 음악에서 0.10초 늦어진다. 판정에는 위 공식으로 계산한 `hitAudioTime`을 사용해 오프셋을 두 번 적용하지 않는다. 로컬 사용자 음원은 사용자가 고른 파일 객체와 세션 안에서 연결하며 파일 절대 경로·음원 데이터·카메라 데이터는 채보에 넣지 않는다.

## 3단계 — 실제로 베는 판정

```text
[목표]
손·방향·시간·궤적을 모두 검사하는 절단 판정을 순수 함수로 구현하라.

[요구사항]
1. 접근 중인 원근 그림 전체와 충돌시키지 않는다. 두 손목 표본의 시각 구간과 노트 판정 창이
   겹치는 노트를 후보로 잡고, 판정 평면의 해당 레인 2D 사각형과 궤적을 검사한다.
   결과가 도착한 현재 시각만으로 후보를 버리지 않는다.
2. 직전 유효 손목 좌표에서 현재 좌표까지의 선분을 사용해 빠른 움직임의 관통을 검사한다.
   단일 프레임의 끝점이 블록 안에 있는지만 검사하지 않는다.
3. 교차 비율로 교차 시각을 보간하고 그 시각을 hitAudioTime과 비교한다.
   표본의 음악 시각과 렌더링용 performance.now를 섞지 않는다.
4. 손의 이동 벡터와 목표 방향의 내적을 사용한다. y가 아래로 증가하는 화면 좌표임을 반영한다.
   any는 방향 제한만 없애며 움직임/시간/손 검사는 유지한다.
5. 허용 시각 ±0.25초, 방향 오차 50도, 최소 이동량/속도는 조정 가능한 초기 가설로 둔다.
   속도는 픽셀/프레임이 아닌 보정된 거리/초로 계산하고 화면 비율을 반영한다.
6. 유효 접촉 뒤 손과 방향까지 맞으면 hit, 틀리면 wrongCut이다.
   접촉이 없던 노트의 miss/untracked 확정은 아래 10~11번의 유예·관측 규칙을 따른다.
   인식이 끊기면 플레이어 표시만 즉시 untracked로 바꾼다. 잠깐 가렸다고 노트를 즉시 소비하지 않는다.
   검출이 없는데 성공/정밀도 수치를 만들지 않는다.
   판정 창 밖에서 검을 휘두른 것은 즉시 wrongCut으로 소비하지 않는다.
7. 각 플레이어의 노트는 pending에서 terminal(hit/wrongCut/miss/untracked)로 한 번만 바뀐다.
   같은 손의 한 스트로크는 블록 하나만 소비한다. 여러 후보면 교차 시각 순서 등 결정 규칙을 고정한다.
   두 손은 독립 입력이다. 같은 노트를 두 손이 동시에 건드리는 경우도 한 번만 처리한다.
8. 스트로크 시작/끝과 재무장 규칙을 정하고 작은 떨림·정지·한 위치 유지·다중 렌더 프레임으로 연타되지 않게 한다.
   예전 '매번 가슴 중앙에 돌아오기' 규칙을 세이버에 무조건 적용하지 않는다.
9. 성공 때 두 조각의 2D 블록 또는 짧은 파티클과 타격음을 낸다. 진짜 메시 절단 엔진은 필요 없다.
10. 늦게 도착한 유효 표본을 먼저 처리하고 miss/untracked를 확정한다.
    초기 정책은 최대 연속 표본 간격 0.20초, 입력 시각 보정 절댓값 최대 0.25초,
    판정 유예 0.45초(두 상한의 합)다. 값은 측정으로 바꿀 수 있지만 유예는 항상 유한해야 한다.
    현재 음악 시각이 창 끝+유예를 넘은 뒤에만 남은 노트를 terminal로 바꾼다.
    확정 뒤 도착한 표본으로 노트를 다시 살리지 않는다. 한 곡의 마지막 1초 여백 안에 확정되게 한다.
11. 요구 손의 연속 유효 관측 구간 합집합이 판정 창의 80% 이상을 덮으면 '관측 충분'으로 보는
    초기 정책을 명시한다. 유예 뒤 pending 노트는 관측 충분이면 miss, 부족하면 untracked다.
    이 비율은 추적 가용성 정책이지 자세 정확도나 건강 평가가 아니다.

[완료 조건]
정상 베기, 틀린 손/방향, 너무 이른/늦은 접촉, 한 프레임 관통, 정지/떨림,
중복 판정, 두 손 동시 접촉, 자유 방향을 의미 있는 자동 검사로 확인한다.
창 끝 10.25초에서 표본 10.20→10.30초의 교차 시각이 10.24초인 경우를 놓치지 않는다.
창 중간 잠깐 가림 뒤 유효 베기와, 최종 관측 부족·유예 초과 표본도 검사한다.
wrongCut/miss가 나와도 음악은 계속된다. 카메라 없는 테스트 결과를 실제 카메라 성공으로 기록하지 않는다.
```

## 4단계 — 카메라 양손과 개인별 보정

```text
[목표]
기존 MediaPipe Pose 손목 데이터를 세이버 입력에 연결하라. 새로운 손가락 모델은 필요를 입증하기 전 추가하지 마라.

[요구사항]
1. 어깨·몸통·손목을 읽고 사람 자신의 왼손/오른손을 유지한다.
   '왼손을 들어 주세요' 연습으로 빨강/L 연결을 확인할 수 있게 한다.
2. 카메라 원본 → 미러 → 플레이어 구역 → 보정된 판정 좌표의 변환을 한 경로로 통일한다.
   반전을 두 번 하거나 화면 왼쪽 손을 항상 해부학적 왼손으로 간주하지 않는다.
   영상의 여백/잘림과 16:9·4:3 비율을 반영한다. 좌표 보정을 바꾸면 이전 궤적을 비운다.
3. 앉은 자세에서 편안한 양손 이동 범위와 어깨 폭을 짧게 보정한다.
   4×3 레인을 그 범위에 매핑하고 상단 레인 때문에 일어서거나 팔을 과도하게 뻗지 않게 한다.
4. 표본은 새 카메라 프레임에서만 생성한다. 추론 결과마다 관측 시각과 세션 ID를 붙인다.
   표본의 시각을 음악 시계로 변환하는 앵커와 오차/지연 가정을 문서화한다.
   손 입력 지연 보정은 채보 offset과 분리한다.
   '관측이 0.10초 늦음' 보정은 표본의 음악 시각에서 0.10초를 빼는 규칙으로 통일한다.
5. 흔들림 완화와 표시용 보간은 허용하되 관측하지 못한 궤적을 예측해서 명중시키지 않는다.
6. 낮은 신뢰도·가림·프레임 정지·탭 이동·좌석 재배정·일시정지/재개 후에는 이전 궤적을 비운다.
   긴 간격 뒤 새 위치로 순간 이동한 선분이 블록을 베지 않게 한다.
   판정 가능한 최대 표본 간격과 이동 속도를 초기값으로 정하고 실제 측정으로 조정한다.
7. 카메라 켜기/끄기/권한 거절/장치 종료를 처리하고 실패 때는 테스트 입력을 명시적으로 선택하게 한다.
   인식이 불안정하면 그 상태를 표시하고 성공 판정을 중단한다.
8. 렌더 프레임과 추론 빈도를 분리한다. 기존 약 12Hz 설정에서 측정부터 하고,
   부족하면 입력 크기·추론 빈도·효과량을 비교한다. Worker는 지원 경로와 이득을 검증할 때만 도입한다.
9. 합성 궤적을 8/12/20Hz 및 프레임 누락 조건으로 재생해 오판정과 누락 수를 비교한다.
   굽은 손 경로를 성긴 표본 사이의 직선으로 근사하는 한계를 기록한다.
   기존 400ms stale 제한을 그대로 '베기 가능한 연속 표본 간격'으로 사용하지 않는다.

[완료 조건]
미러·좌표·손 구분·추적 소실/재등장·저속/고속 이동·리사이즈 경계가 검증된다.
실제 사람이 가능하면 양손 각 방향을 반복 시험하고 누락/오판정 수를 기록한다.
사람 시험을 하지 못하면 '카메라 모델 연결 확인/실기 대기'로 구분한다.
```

## 5단계 — 1인 한 곡 MVP와 전체 화면

```text
[목표]
곡 선택부터 종료까지 1인 세이버 게임을 완주할 수 있게 하라.

[요구사항]
1. 곡·채보 선택 → 카메라/테스트 입력 → 보정/짧은 연습 → 시작 → 카운트다운 → 한 곡 → 완료를 연결한다.
2. 기존 FullscreenController와 비동기 세대 토큰을 재사용한다.
   실제 클릭에서 전체 화면을 요청하고 거절이면 정확히 알린 뒤 창 모드에서도 진행한다.
3. Esc/탭 숨김/일시정지 때 음악·판정·궤적·예약 타격음을 함께 멈춘다.
   재개 때 과거 궤적과 예약음을 버리고 현재 음악 시각에서 복원한다.
4. 그만하기/결과 닫기/모드 변경/재시작 때 노트 상태와 음성, 시계, 전체 화면을 정리한다.
   느린 audio.play/전체 화면 응답이 끝난 게임을 다시 시작시키지 않게 한다.
5. 한 곡 끝에서 한 번만 결과를 보여준다. 완료/놓침/인식 안 됨을 구분하되 보상·랭킹·HP는 넣지 않는다.
6. 기존 150초 창작곡에 대응하는 실제 채보를 포함한다.
   사용자 120~180초 음원에 채보가 없으면 BPM/offset으로 만드는 '간단 연습 패턴'을 제공하거나
   호환 JSON을 직접 선택하게 한다. 자동으로 음악의 실제 박자를 분석했다고 표시하지 않는다.
7. 전신 스트레칭의 서기/누워서/커플과 225초 종료 흐름에 영향을 주지 않는다.

[완료 조건]
한 곡 종료·도중 정지·재개·그만하기·다시 시작·오디오 실패·전체 화면 거절을 브라우저에서 확인한다.
실제 전체 화면은 document.fullscreenElement와 실제 표시 상태로 확인한다.
자동 시각 이동 검사와 사람이 120~180초 연속 플레이한 검사를 분리한다.
이 단계 통과는 1인 MVP이며 2인 완료로 표시하지 않는다.
```

## 6단계 — 한 카메라에서 최대 2인

```text
[목표]
같은 음악으로 두 사람이 각자의 블록을 베게 하라. 로컬 한 PC·한 카메라만 사용한다.

[요구사항]
1. 1인/2인 선택을 제공한다. 2인은 상단 무대 좌우 P1/P2, 하단 카메라는 한 영상에 두 구역을 표시한다.
2. 두 플레이어 각각 4×3 레인과 왼손/오른손 세이버를 가진다. 총 네 손이다.
3. 음악과 불변 채보 데이터만 공유한다. 보정값, 표본, 스트로크, 판정 상태, 효과 상태는 플레이어별이다.
   같은 note.id를 두 사람이 각각 한 번씩 맞힐 수 있게 한다. 전역 hits Set으로 상대 노트를 제거하지 않는다.
4. 카메라 거울 화면의 왼쪽 좌석은 P1, 오른쪽은 P2다. 결과 배열 순서를 사람 ID로 쓰지 않는다.
5. 가운데 경계·같은 구역 두 사람·가림·자리 이탈에는 해당 입력을 비운다.
   자리를 바꾸면 신원 추적이 아니라 좌석 재배정이다. 재보정/새 안정 표본 뒤에만 입력을 재개한다.
6. 한 사람이 사라져도 다른 사람은 계속할 수 있다. 사라진 플레이어는 untracked로 표시하고
   늦게 돌아왔을 때 지난 블록을 몰아서 판정하지 않는다. 다시 연속으로 잡힌 손 궤적부터 시작한다.
7. 네 손이 서로 다른 색/위치/방향으로 움직이는 테스트 입력 또는 기록된 합성 좌표를 제공한다.
   2인 키보드 시험은 대상 플레이어와 손을 선택하는 방식을 명시한다.
8. 2인 선택 변경 중 모델 재설정과 입력을 잠그고 실패 시 복구한다.

[완료 조건]
같은 노트를 P1/P2가 각각 명중, 두 손 동시 입력, 한 사람 이탈/복귀,
가운데 경계, 검출 순서 반전, 자리 교환에서 상대 판정이 섞이지 않는다.
실제 두 사람 플레이와 합성 좌표 검사를 별도 기록한다.
둘 사이를 손으로 가로질러야 하는 채보나 협동 강제 동작은 넣지 않는다.
```

## 7단계 — 빛·블록 절단·음악과 음성

```text
[목표]

[요구사항]

8. 원작 그래픽/음악을 가져오지 않는다. 새 이미지가 실제로 필요한 경우만 창작 도구를 사용한다.

[완료 조건]
```

## 8단계 — 선택 확장: 로컬 채보 편집기

```text
[목표]
게임 MVP를 완성한 뒤, 음악을 들으며 v1 JSON 채보를 만드는 간단한 편집기를 추가하라.

[요구사항]
1. 게임 플레이와 별도의 편집 상태를 만들고 녹화/채보 작성임을 명확히 표시한다.
2. 재생·일시정지·구간 이동·시간 표시·BPM·offset·박자 스냅을 제공한다.
3. 손, 방향, 레인 열/층을 선택한 후 기록 키로 현재 음악 시각에 노트를 추가한다.
   예: 1~4는 열, Q/W/E는 층, Z/X는 손, 방향키는 방향, Space는 기록.
   직접 쓰는 키맵을 화면에 보여주고 기존 플레이 입력과 충돌하지 않게 한다.
4. 기록 값은 note.time = audio.currentTime - offsetSeconds다.
   스냅은 채보 시간에서 수행한다. raw time과 offset 적용 후 hit/spawn 시각 모두
   플레이어 로더와 같은 접근 시간·곡 범위·끝 1초 여백 규칙으로 검증한다.
   재생 시 offset을 다시 한 번만 적용한다.
5. 선택 노트 삭제·시간/방향 수정·실행 취소·구간 반복 미리보기를 제공한다.
   편집 중 탐색할 때 지난 노트의 타격음/판정을 몰아서 실행하지 않는다.
6. JSON을 브라우저 다운로드로 내보내고 같은 검증기로 다시 가져온다.
   사용자가 고르지 않은 파일을 덮어쓰거나 오디오/개인 경로를 내보내지 않는다.
7. 비정상 JSON/과대 파일/중복 ID/노트 충돌은 플레이어 로더와 같은 규칙으로 거절한다.

[완료 조건]
작성 → 내보내기 → 다시 가져오기 → 동일 음악에서 동일 시각/손/방향/레인으로 재생된다.
원본 음원이나 세트 데이터를 바꾸지 않고 편집 중에도 게임 모드로 돌아갈 수 있다.
```
