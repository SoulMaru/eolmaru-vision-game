# 연습 음악·접근 속도·계속 베기 독립 검토

검토엔진, 2026-09-27 KST. 시작 기준은 변경 없는 `453f4e1`이었다. AGENTS와 기존 chart/input/core/game/editor/music 계약을 읽고 독립 검사를 작성했다. 검토엔진의 수정 범위는 `tests/review-training.test.mjs`, 이 문서, 승인된 `tests/review-music.test.mjs` 호환 수정이다. 앱 소스·음악 제작·커밋은 수정하지 않았다.

**최종 독립 자동 검사 131/131 통과, 실패·스킵 0, 316.2347ms.** 기존 104개를 유지하고 새 연습 검사 27개를 추가했다. 신규 7곡 전체 디코드와 PCM 피크/RMS도 직접 재계산했다. 아래 브라우저 149개는 생성엔진이 실행한 결과이며 검토엔진의 별도 브라우저 실행으로 표시하지 않는다. 확인한 범위에서 남은 개발 차단 문제는 발견하지 않았다. 사람 청취와 실제 카메라 조작성은 미검증이다.

## 검증한 최종 계약

| 범위 | 독립 검사와 소스 대조 결과 |
|---|---|
| 곡과 보존 | 손 리듬 선택 10곡 중 새 7곡은 80/90/100/110/120/130/140 BPM. 전체 음악 12개 해시는 서로 다르다. 기존 5곡 Ogg/메타 10개, 코치 31개·칭찬 5개와 두 manifest의 기준 해시를 보존했다. |
| 접근 속도 | 0.6/1.0/1.6배에서 `leadSeconds = 1.8 / speed`, `spawnTime = max(0, hitTime - leadSeconds)`. hit/end/BPM과 원본 노트는 불변이다. |
| 출현 간격 | 4박 설정은 원본의 시각 묶음 0,2,4…만 실행한다. 양손 동시 묶음은 함께 보존한다. `chart`와 편집/export는 전체 원본, `playChart`만 파생한다. |
| v1 호환 | 지속 타겟은 `kind:'sustain'`, 자유 방향, 유한한 0.5~6초이며 곡 끝 1초 여유가 필요하다. 기본 단타는 선택 필드를 생략한다. JSON 왕복·동결·잘못된 길이/타입/곡 끝·같은 손 또는 같은 칸의 end+0.5초 여유를 검증했다. |
| 이동 누적 | 같은 손의 유효 이동을 타겟 중심 ±0.55칸과 활성 시간에 잘라 합집합으로 누적한다. 중복 선분, 정지/저속 떨림, 다른 손, 범위 밖, 저신뢰도, 추적 소실, epoch 경계, 시계 점프는 가짜 진행을 만들지 않는다. |
| 최종 성공 | 활성 기간의 이동 60% 이상과 마지막 25% 구간의 유효 이동이 모두 필요하다. 종료 전에는 성공하지 않는다. 조건이 이미 충족되면 정확한 `endTime`부터 한 번 성공하며 미충족만 `endTime + .45`까지 늦은 표본을 기다린다. |
| 유예와 실패 | 정확한 grace 경계에 도착한 유효 표본은 회복 가능하고 grace+1µs는 거절한다. 미완료는 유예가 지난 뒤 관측 비율 80% 이상이면 miss, 그 외 untracked다. 6초 정상 추적/정지는 관측 정리 때문에 untracked로 바뀌지 않는다. |
| 등급·중단·독립성 | 최초 유효 교차 시각의 타이밍 등급과 `sustainAccuracy`를 분리한다. 중간 이동은 칭찬/최종 hit를 내지 않는다. 실제 `SaberGame` 연결에서 종료의 onHit 1회, pause 진행 보존과 epoch 절단, seek의 시작한 타겟 skipped, 새 시작 초기화, 1/2인별 독립 상태를 확인했다. |
| 표본 빈도 | 같은 연속 원형 경로를 8/12/20Hz로 입력해 모두 종료 시각에 한 번 성공했다. 이는 합성 경로 검사이며 실제 카메라의 프레임률이나 정확도 실측이 아니다. |

핵심 근거는 [saber-chart.mjs](../src/saber-chart.mjs)의 v1 검증·`generateTrainingChart`·`applyTrainingSettings`, [saber-core.mjs](../src/saber-core.mjs)의 공간/시간 클립·관측·`advance`, [saber-game.mjs](../src/saber-game.mjs)의 원본/실행 채보 분리·입력 리셋·최종 이벤트 연결이다. 편집기는 원본 선택 필드를 열기/수정/JSON에 보존하며, app은 설정을 진행/로딩 중 잠그고 기존 곡/채보 비동기 세대 검사를 유지한다.

## 독립 실행 이력과 발견→수정

재현 명령은 `node --test tests/review-training.test.mjs`, `node --test tests/review-music.test.mjs tests/review-training.test.mjs`, `npm test`다. 기존 0.5의 104개 결과를 이번 실행으로 재사용하지 않았다.

1. **TR00 — 기존 음악 JSON 줄바꿈 이식성.** clean 기준의 CRLF 작업 파일과 Git LF blob이 달랐다. 생성엔진 승인 후 기존 음악 검사에서 JSON만 LF 정규화하고 Git 원본의 고정 SHA를 사용했다. Ogg/음성은 엄격한 바이트 비교를 유지했다. 기존 음악 9개+새 보존 2개는 11/11 통과, 145.26ms였다.
2. **TR01 — 같은 손/칸 해제 간격 1µs.** end=13초 뒤 다음 노트 13.499999초가 기존 `-1e-6` 허용 때문에 통과함을 독립 검사로 재현했다. 처음 새 검사 19개 중 1개가 실패했다. 생성엔진이 부동소수 잡음 허용을 `1e-9`로 좁힌 뒤 13.499999는 거절하고 정확한 13.5는 허용하는 회귀가 통과했다.
3. **TR02 — 성공을 무조건 유예하면 끝박자와 연출이 어긋남.** 생성엔진이 브라우저 점검 중 발견했다. 충분한 이동을 완료한 경우 종료 시각에 성공하고, 부족한 경우만 지연 표본을 기다리도록 수정했다. 검토엔진은 end−1µs pending, exact end hit, grace 경계 회복, grace+1µs 거절, 미완료 miss/untracked 유예를 독립 검사에 반영했다.
4. 정책 변경 전 새 26개+음악 9개는 35/35 통과, 217.4063ms, 전체는 130/130 통과, 364.8143ms였다. **최종 정책 반영 후 새 27/27 통과, 212.6427ms, 이어 전체 131/131 통과, 316.2347ms**였다. 이전 130개 결과는 최종 정책 검증과 구분한다.

새 제작기의 줄바꿈 의심은 실제 바이트 검사로 철회했다. 파일의 CR 바이트는 0, Git 속성은 `eol=lf`, 실제 제작기 SHA는 메타데이터의 `36c80db719ba62b222ab37f18d194aa57666c451be02a57000888bd43a64e5c8`과 일치했다. 콘솔의 줄바꿈 표시만으로 파일 해시 이상을 판정하지 않았다.

## 신규 7곡 독립 파일 검사

최종 Ogg를 각각 FFmpeg `-v error -xerror -i <file> -f null -`로 전체 디코드해 오류 0을 확인했다. ffprobe는 전부 44,100Hz·스테레오·Vorbis였다. 이어 `pcm_f32le` 전체를 메모리로 디코드해 유한한 표본, 프레임 수, peak, RMS를 직접 재계산했다. 중간 WAV/PCM 파일은 만들지 않았다.

| BPM | ffprobe 초 | 전체 디코드 프레임 | 독립 peak | 독립 RMS |
|---:|---:|---:|---:|---:|
| 80 | 144.000000 | 6,350,400 | 0.8379021 | 0.1829811 |
| 90 | 149.333333 | 6,585,600 | 0.8179566 | 0.1838724 |
| 100 | 153.600000 | 6,773,760 | 0.8240148 | 0.1876971 |
| 110 | 148.363628 | 6,542,836 | 0.8302754 | 0.1873450 |
| 120 | 152.000000 | 6,703,200 | 0.8412361 | 0.1917510 |
| 130 | 147.692290 | 6,513,231 | 0.8322595 | 0.1924631 |
| 140 | 150.857143 | 6,652,800 | 0.8232408 | 0.1896479 |

각 프레임 수는 제작 메타데이터와 정확히 같고 peak/RMS는 1e-6 안에서 같았다. 모두 비무음·finite·디지털 full scale 미만이었다. 이것은 음질이나 듣기 편안함의 평가가 아니다. LUFS/true peak는 제작 담당의 수치이며 검토엔진이 그 두 값을 다시 계측했다고 주장하지 않는다.

새 검사에서 실제 파일 크기/SHA, Ogg 마지막 granule의 표본 길이, 4/4 마디 공식, 메타데이터, 첫 8개 킥의 정수 표본 그리드, 고유 seed/훅, 연속 섹션, 제작기/helper 해시, 양손 지속 타겟 포함 채보를 대조했다. 생성 이벤트 그리드의 검증이며 완성 음원에서 BPM을 자동 추정한 시험은 아니다. 새 Ogg 총 14,301,678 bytes, 기존 포함 전체 12곡 해시는 고유하다.

F 원본을 읽기만 해서 얻은 현재 SHA도 `de182299dbf5216aaeaaa08303ae19c8785a537518b9ba1d3e44f6164edf3df3`으로 기록과 일치했다. 원본/기존 음악/음성을 검토엔진이 수정하거나 재인코딩하지 않았다. 배포 음원 재생에 Python·F·온라인 생성 서비스가 필요하지 않는다.

## 생성엔진 브라우저 증거의 교차검토

생성엔진은 최신 정책에서 `tests/browser-training.js` **68/68 통과**를 보고했고, 검토엔진은 저장된 `test-results/training-browser.json`의 68개 항목과 `training-hold.png`를 직접 읽었다. 저장된 화면에서 L 계속 베기, 남은 초, 시간 고리와 초록 진행 막대, 검 끝을 확인했다.

- 신규 7곡 실제 Ogg 로딩/음악 시간 증가/끝으로 seek 후 종료, 곡별 편집기의 지속 타입·기간·원본 JSON 왕복, 곡 변경 중 설정 보존.
- 0.6배/4박 및 1.6배/2박, 실행 중 잠금, 원본 보존, 음악 재생속도 1, 설정 저장.
- 실제 브라우저 포인터 이벤트를 프레임마다 계속 보내고 중간에 일시정지한 시험. 80 BPM n5는 end 13.5초, 최종 hit 13.503126초로 보고됐다. 최초 교차 37.6008% 그레이트와 유효 이동 84.4247%를 별도로 기록했다.
- 2인 high/low/reduced 렌더, 기존 서기 225초 구성, 외부 리소스 요청 0·브라우저 예외 0.

초기 브라우저 길이 실패는 Chromium이 Vorbis를 약 2.902ms 길게 표시해 발생했다. 최종 UI 시험은 20ms 여유를 주되 Ogg granule/전체 디코드 파일 시험은 1표본 기준을 유지한다. 초기 25ms 간격 포인터 자동화에서는 프레임 사이 정지 표본이 생겨 이동 40.8%로 정상 miss였다. 이후 RAF마다 새 위치를 보내 연속 움직임을 시험했다. **저빈도 실제 마우스/터치패드의 체감 문제는 H09로 남아 있으며 자동화 변경으로 장치 문제가 해결됐다고 표시하지 않는다.**

생성엔진이 같은 코드에서 기존 flow 15/15, profiles 8/8, saber-editor 27/27, music 31/31도 다시 실행했다고 보고했다. 신규 68개와 합쳐 **이번 브라우저 149개**다. 생성엔진의 최종 전체 자동 회귀도 별도로 131/131, 313.7067ms였으며 독립 실행과 중복 합산하지 않는다.

브라우저 증거는 실제 사람 카메라 사용 또는 7곡 전체를 실시간으로 완주한 청취 시험이 아니다. JSON에도 `cameraUsed:false`, `fullLengthHumanPlayback:false`가 명시돼 있다.

## 정리와 남은 검증

관측은 최대 길이 6초와 유예를 덮는 최근 7초만 유지한다. 연속 지속 이동 구간은 병합하며 tap의 stroke 소비 규칙과 분리한다. 렌더는 노트 최대 48개·잔상 최대 20개·효과 최대 16개, game 효과 배열은 24개로 제한한다. 성공 피드백의 최대 8버스트/공유 음량/중단 정리는 기존 독립 회귀가 이번 전체 실행에서도 통과했다. 실제 새 음악까지 합친 최대 믹스 음량이나 카메라 성능을 별도 측정한 것은 아니다.

새 7곡은 기존 제작기 helper를 재사용하고 기본 단타 생성기는 유지한다. 원본 채보를 삭제하지 않고 실행용 필터만 적용한다. 생성엔진 최종 자산 감사는 99개·52,938,273 bytes, 누락/중복/음성/음악/외부 URL 문제 0으로 보고됐다. 음악·음성의 별도 중복 재생성, 자동 BPM 분석, 손가락 쥠 인식, 실제 VR 충돌, 온라인 순위 기능을 이번 완료 범위에 넣지 않는다.

사람 청취, 새 반복 동작의 편안함, 실제 1/2인 카메라 완주·가림·체감 지연·도달 범위는 [ISSUES](ISSUES.md)의 H01~04/H08/H09와 [TRAINING_PLAN](TRAINING_PLAN.md)의 TR10에 남긴다. 자동 검사·포인터 입력·파일 파형과 사람의 경험은 서로 대체하지 않는다.
