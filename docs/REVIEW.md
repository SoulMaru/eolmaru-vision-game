## 최신 범위 검수 결과

사용자의 최신 자세 지정은 **전신 스트레칭 기본=서서**, 추가 **누워서/커플**이며, **손 리듬만 앉아서 손 동작**이다. 의자 전신 루틴은 현재 제품 범위에서 제외한다. 서기에서 의자는 균형을 위한 지지물로만 사용할 수 있다. 서기 기본값·진행 중 프로필 잠금·누운 매트 예시·커플의 자동 2인/인원 잠금·종료 시 초기화를 통합 소스로 재검수했다. 커플은 서로 당기거나 밀지 않는 독립 동작이며, 실제 두 사람이 참여하는지는 코드만으로 확인하지 않는다.

사용자 후속 요구에 따라 보상·레벨·콤보 경쟁·기록 누적을 표시하는 복잡한 게임 구조를 제외한다. 최신 구조는 **곡 선택 → 단일 세션 → 완료**, 전신 스트레칭은 **기본 원곡 3개의 앞 75초씩 재생하는 225초 세트**, 손전용 리듬은 **별도 한 곡**이다. 사용자 로컬곡은 손 리듬에서만 사용하며 원본 길이 120~180초로 제한한다. 목·어깨 회전·무릎·햄스트링·종아리·발목은 타이머와 예시 안내만 제공한다. 가슴 열기와 좌우 옆구리의 잘 보이는 팔·몸통 형태만 2D 일치도로 비교한다.

**현재 독립 시험은 27개 통과, 0개 실패다.** 명령: `node --test tests/review-*.test.mjs`. 최신 검수는 서기/누워서/커플의 **각 13구간·225초**, 모든 프로필의 시간 경계·예시 좌표, 바닥의 전 구간 무채점, 커플 2인 조건, 실제 음성 파일 참조, 누운 그림의 좌우 다리 구분을 포함한다. 로컬곡 120/180초 경계·무효 메타데이터·3개 고유 Ogg와 기존 손 입력 검수도 유지한다. 옛 150초 운동 일정과 의자 전신 구성은 정리했다. 초기 14→16→22개 과정은 검수 이력으로 보존한다.

## 구현 시 흔한 오류 및 검토 규칙

1. 포즈 결과 배열 순서는 사람 식별자가 아니다. 2인 모드는 반전된 화면 중심 좌표로 좌우 구역을 고정 배정한다. 두 사람이 자리를 바꾸면 구역 소유자가 바뀌는 것이 MVP 정책이며 개인 신원 추적이라고 설명하지 않는다.
2. CSS 반전만 적용하면 표시와 판정 방향이 어긋날 수 있다. 화면 기준 손짓과 카메라 반전은 한 번만 적용한다.
3. 16:9 정규화 좌표의 x와 y는 다른 축 비율이다. 운동 일치도는 축별 정규화 또는 영상 가로세로 비율 보정이 필요하다.
4. 단일 검출·한쪽 손 누락에서 이전 사람/손 좌표를 유지하면 유령 득점이 발생한다. 현재 프레임 유효성과 최대 결과 유효 시간을 검사한다.
5. 손을 뻗은 자세를 매 프레임 터치로 처리하지 않는다. 중립 복귀·방향 진입 이벤트·쿨다운을 검토한다. 상태 초기화 시도 같은 방향 재진입의 무료 연타가 되면 안 된다.
6. 모델이 추정한 2D 운동 점수는 유연성 향상이나 의학적 자세 교정의 증명이 아니다. 편안한 범위 내 따라하기 게임으로 제시하고 실제 운동 성과 진단은 제공하지 않는다.
7. 배경 탭·일시정지·재시작·카메라 장치 해제에서 오디오 시간, 노트 시간, 입력 상태가 함께 정리되는지 확인한다.

## 실제 카메라 수동 재현 절차

자동 검증과 별개로 사용자가 다음 절차를 실행해야 실기 검증이 완성된다.

1. 인터넷 연결을 끈 상태에서 로컬 실행. 화면과 곡을 불러온 뒤 카메라 허용. 각 리소스의 로컬 로딩 확인.
2. 손 리듬에서 의자에 앉아 손만 네 방향으로 움직임. 어깨·골반·손은 카메라 기준점으로 보이게 하되 다리 동작을 요구하지 않는지, 거울 화면과 방향 반응이 일치하는지 확인.
3. 손을 한 방향에 5초 유지. 연속 노트가 자동으로 맞지 않아야 함. 중립으로 돌아온 뒤 다시 진입하면 새 입력 가능.
4. 손/어깨/엉덩이를 가리거나 화면 밖으로 나감. 그 슬롯의 판정이 멈추어야 하며 복귀 순간 자동 득점하지 않아야 함.
5. 두 사람이 화면 좌우에 선 뒤 한 사람만 화면 밖으로 나감. 남은 사람이 다른 슬롯까지 득점하지 않아야 함. 두 사람을 동일 구역에 모으면 반대 슬롯이 비어야 함.
6. 서서 전신 세트를 확인. 팔·몸통 목표를 따라한 뒤 카메라에서 조금 멀어지고 좌우로 이동해 같은 자세의 일치도가 과도하게 달라지지 않는지 확인. 목·하체 단계에는 정확도 대신 시간 안내가 표시되어야 함. 누워서 프로필은 모든 구간이 시간 안내이며, 커플은 두 사람이 간격을 두고 각자 움직여야 함.
7. 손 리듬 1곡과 전신 225초 세트를 각각 완주. 전신은 75초·150초에 한 번씩 다음 곡으로 넘어가고 225초에 완료되어야 함. 일시정지·재개·재시작·카메라 끄기에서 이전 입력이 새 세션에 새지 않아야 함.
8. 1인/2인 각각 표시 추론 지연과 체감 음악 끊김 기록. 미달 시 낮은 해상도·낮은 추론률을 선택하고 기록.
9. 손 리듬의 사용자 파일에서 120초/180초 정상 파일, 짧거나 긴 파일, 디코드할 수 없는 파일, 취소, 같은 파일 재선택을 확인. 잘못된 파일은 이전 곡을 유지해야 하고 파일은 서버에 전송되지 않아야 함. 실제 사용자 코덱·BPM·첫 박자 오프셋은 자동 시험과 별도 확인 사항이다.

시험 범위: 2인 순서 독립 배정·동일 구역/경계/가림 배제, 미러 좌표 및 원본 보존, 네 방향 중립 재무장, 자세 유지/방향만 변경한 연타 방지, 누락 및 400ms 초과 추적 단절 후 재진입 억제, 개별 손목 가림, 신체 위치·크기 변화, 중복 판정·미스 후 계속 진행·플레이어 입력 분리, 차트 범위/밀도, 일치도의 이동·배율·16:9 좌표 보정, 반대 자세 구분, 사용자 곡 120/180초 경계 및 무효 기간 거절, 225초 세트 및 안내 동작 무채점.

운동 판정 구현은 상·하완 네 벡터의 방향 유사도와 몸통 기울기를 조합하고, 옆구리 동작에서는 몸통 기울임 차이를 추가 비교한다. 목표 좌표는 정사각형 그림 좌표이고 실제 영상 x축에 가로세로 비율을 적용한다. 수정된 UI는 같은 비율로 목표 캐릭터를 그린다. 이는 카메라 크기·위치에 강인한 게임 일치도이며 정밀 관절각 측정이나 유연성 진단은 아니다.

남은 실기 검수: 실제 사람 두 명의 추적 및 공간·조도·성능, 손짓/음악 체감 동기, 스피커/헤드폰 청취와 코치 음량 균형. 코드와 합성 영상의 통과를 실제 사람의 카메라 플레이 통과로 바꾸지 않는다.

### 검토 발견 R01 — 옆구리 목표의 몸통 구분

초기 코어에서 `targetPose('left')`의 상반신 좌표(`i < 23`)를 x축으로 +0.08 옮겨 몸통을 수직으로 세워도 왼쪽 목표에 99점이었다. 팔 방향은 동일하나 몸통 기울임이 다른데 거의 만점이므로 생성엔진에 비율 기반 몸통 기울임 차이 반영을 요청했다. 실제 큰 동작을 추가 요구하는 것이 아니라 현재의 작은 목표 기울임과 수직을 구분하려는 수정이다. 양쪽 목표에 수직 몸통 점수 85 이하를 요구하는 회귀 시험이 이 결함으로 실패함을 확인했다. **해결:** 생성엔진이 몸통 기울임의 각도 차이를 별도 반영했다. 독립 재실행에서 수직 몸통 점수 제한, 이상적 목표 100점, 위치·크기·16:9 불변 시험 모두 통과했다.

확인한 연결상의 장점: 포즈 결과를 매 검출 새 슬롯 배열로 교체하고 미검출 슬롯을 null로 넘긴다. 화면 카메라 반전과 랜드마크 x 반전을 각각 한 번 적용한다. 음악 시각이 채보·판정 기준이다. 카메라 트랙 `onended` 및 `pagehide` 종료 처리가 있으며 네트워크 경로는 로컬 자산을 가리킨다. 프레임 간격이 1초 이상 끊기면 진행 중 게임을 일시정지한다.

추가로 생성엔진의 브라우저 시험 코드를 검토하여, 버튼에 focus만 두고 `document.dispatchEvent`를 호출하면 BUTTON 초점 회귀를 검증하지 못한다는 점을 전달했다. 방향 이벤트는 실제 초점 요소에서 전파해야 이 경로를 시험할 수 있다.

생성엔진이 공유한 별도 브라우저 결과: 합성 카메라 입력에서 로컬 GPU 모델 초기화 성공, 약 11fps / 17ms, 런타임 외부 요청 0건. 이 값은 실사용 카메라·실제 두 사람의 성능 보장값이 아니며 독립 검토엔진이 직접 측정한 값도 아니다.

최신 생성엔진 브라우저 보고는 14개 검사 통과다: 버튼 초점 이후 2인 입력, 일시정지/재개, 75초 단위 곡 전환의 중복 방지, 225초 종료, 안내 모드의 일치도 null, 로컬 음성과 외부 요청 없음. 검토엔진은 전환 함수의 즉시 잠금, 세대 토큰 취소, 누적 시각 `index×75+min(currentTime,75)`, 지연 ended 이벤트의 `audio.ended` 확인을 소스로 재검토했다. 실제 사람의 운동 완료 확인을 뜻하지 않는다.

서기/바닥/커플 추가 통합에서 생성엔진은 별도 브라우저 프로필 검사 8개 통과를 보고했다. 검토엔진은 `state.profile='standing'`, 기본 option, 시작 시 스트레칭 선택을 직접 읽어 기본값을 확인했다. 커플 선택 시 2인 모델 설정을 기다리는 동안 입력/UI를 잠그고 추론도 건너뛰는 것을 확인했다. 누운 프로필은 `routineAt` 결과 전 구간 `match=null`이며 결과에도 시간·음성 안내임을 표시한다. 바닥 예시는 위에서 본 그림이라고 명시하고, 서기/커플 캐릭터는 같은 x/y 배율을 유지한다.

### 음악·기획 문서 교차 확인

`docs/MUSIC.md`, `docs/PLAN.md`, `docs/DECISIONS.md`, `tools/music-compose.py`를 확인했다. F 제작소의 확인된 함수만 AST로 추출해 호출하며 전체 모듈을 실행하지 않는 코드와 설명이 일치한다. 음악은 F 경량 합성 함수와 새 편곡의 결합이며 ACE-Step 신경망 사용으로 오인시키지 않는다. 배포 재생에는 Python/F드라이브가 필요 없고, 문서에 실제 청취·체감 동기·실기 2인·성능 미검증이 명확하다.

검토엔진이 직접 계산한 배포 Ogg SHA-256은 `a940becf5467a95501eed896ac1b860cc90c764239ed18ed2eac5c7090d79cb3`로 메타데이터와 일치한다. 150초·112BPM·형식/음량 측정은 기획엔진의 기록과 일치하며, 검토엔진은 별도 청취나 재합성을 하지 않았다.

전신 확장에서 `maru-breeze.ogg`, `maru-sunset.ogg`를 추가했다. 검토엔진의 파일 시험에서 세 파일 모두 Ogg 헤더가 있고 SHA-256이 서로 다른 실제 파일임을 확인했다. 각각 150초 원곡의 앞 75초를 사용하며 3개 조각의 합은 225초다. 추가곡의 전체 디코드·길이·음량 검사는 기획엔진 기록을 따른다.

### 추가 요청의 F 음성 기능 교차 확인

`docs/VOICE.md`, `tools/voice-generate.mjs`, `tools/voice-sapi.ps1`를 읽었다. F 제작소의 설치된 한국어 SAPI 음성을 사용해 로컬 음성 파일을 만드는 구조이고, 새 모델 또는 온라인 TTS를 실행하지 않는다. 임시 파일 삭제는 해당 작업이 만든 임시 디렉터리임을 검사한 뒤 수행한다. F가 없는 다른 PC에서는 프로젝트 소유 어댑터를 사용하며, 완성된 게임 재생에는 F나 SAPI가 필요 없다.

처음 제공된 음성 9개는 139,204 bytes였고 첫 전신 확장은 19개였다. 서기/바닥/커플 안내 추가와 미사용 의자/상체 음성 7개 정리 후 **최종 31개, 799,646 bytes**다. 검토엔진이 최신 manifest와 실제 31개 Ogg의 SHA-256 및 크기를 직접 대조해 전부 일치하고 31개 해시가 고유함을 확인했다. 모든 프로필의 음성 참조가 실제 로컬 파일에 연결되며 서기/커플 원고에 예전 '의자에 앉아' 지시가 없다는 시험도 통과했다. 사람 청취·한국어 발음·음악/음성 균형 검증은 별도 대기다.

통합 소스 최종 확인: 음성 파일 경로는 manifest에서 로드하며 끄기/음량 설정, 재생 실패 시 게임 계속 진행, 이전 음성 중지, 음성 중 음악 음량 축소/종료 후 복구를 구현했다. 운동 안내는 큰 동작 블록의 index 기준 한 번만 재생하여 2~5초의 짧은 동작/휴식 주기마다 반복하지 않는다. 음성을 끄더라도 화면 안내가 유지된다. 실제 발음·음량 만족도는 사람 청취 대기다.

## 검토엔진 최종 판단

발견한 코어 및 UI 연결 결함 R01~R09는 수정 코드와 독립 회귀 시험으로 확인했다. 서기 기본/누워서/커플의 225초 세트와 앉아서 하는 손 리듬을 포함한 **27개 독립 시험이 통과**했고, 현재 소스 검수에서 전달을 막는 미해결 결함은 발견하지 않았다. 최종 README/HANDOFF의 서기 기본·프로필별 13단계·음성 31개 및 의자 손 리듬 분리 설명도 새 범위와 일치함을 재확인했다. 실제 1인/2인 움직임, 바닥에서의 영상 가시성, 카메라 공간/조명, 체감 지연·청취 및 사용자 음원 코덱/BPM은 수동 검증 대기다.
